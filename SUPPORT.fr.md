# Obtenir de l'aide

*[English version](SUPPORT.md)*

ZASPR Kit est développé publiquement. Posez vos questions en public dès que possible : la réponse servira à la prochaine personne qui se pose la même question.

## Où aller

| Vous voulez… | Rendez-vous sur |
|---|---|
| Comprendre comment ça marche | La [documentation](https://nathanaelzie.github.io/zaspr-kit/docs/introduction/) et le [playground](https://nathanaelzie.github.io/zaspr-kit/playground/) |
| Demander comment faire quelque chose | [Discussions, Q&A](https://github.com/NathanaelZie/zaspr-kit/discussions/categories/q-a) |
| Proposer une idée ou montrer ce que vous avez construit | [Discussions](https://github.com/NathanaelZie/zaspr-kit/discussions) |
| Signaler un bug | Une [nouvelle issue](https://github.com/NathanaelZie/zaspr-kit/issues/new/choose), avec le modèle « Bug report » |
| Demander un utilitaire, une variante ou un composant | Une [nouvelle issue](https://github.com/NathanaelZie/zaspr-kit/issues/new/choose), avec le modèle « Feature request » |
| Signaler une faille de sécurité | En privé, comme expliqué dans [SECURITY.fr.md](SECURITY.fr.md). Jamais dans une issue publique |

## Bien poser sa question

- Indiquez vos versions de jx_cli (`dart run jx_cli:jx --version`), de Dart et de Jaspr.
- Montrez les classes, la section de `jx.yaml` ou la commande, et le CSS ou le message obtenu.
- Gardez un exemple court : quelques classes se vérifient plus vite qu'un projet entier.

## À quoi s'attendre

ZASPR Kit est maintenu sur du temps personnel. Les questions et les issues sont lues régulièrement, mais sans délai de réponse garanti. Chaque participant respecte le [code de conduite](CODE_OF_CONDUCT.fr.md).
