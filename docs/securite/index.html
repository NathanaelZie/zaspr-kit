Sécurité

Les classes peuvent venir d'un contenu que vous ne contrôlez pas. JX les traite comme des entrées non fiables.

Le risque

Une valeur arbitraire est la seule partie d'une classe recopiée dans le CSS. Sans contrôle, c:[red;}body{display:none] fermerait sa règle et en ouvrirait une autre.

Ces classes ne produisent aucune règle et déclenchent un avertissement :

c:[red;}body{display:none]
bg:[url(javascript:alert(1))]
c:[</style><script>alert(1)</script>]
c:[expression(alert(1))]

Ce qui est refusé

Risque Refusé dans une valeur arbitraire
Sortie de la déclaration ; { } ! \ /* */
Sortie d'une balise style <
Chargement de code javascript: vbscript: expression() @import
URL de données data: hors image et police
Valeur mal formée Parenthèses ou guillemets non fermés

À savoir

Le contrôle est fait deux fois : par le parseur, puis par les règles au moment de générer le CSS. Un jeton construit à la main ne le contourne pas.

Limites de taille

  • Une classe : 512 caractères.
  • Une valeur arbitraire : 512 caractères.
  • Variantes cumulées : 8, sans répétition.

L'analyse et l'extraction s'exécutent en temps linéaire, quelle que soit l'entrée.

Compilation à l'exécution

Si vous compilez dans le navigateur des classes saisies par un utilisateur, le moteur applique les mêmes contrôles. JxParser.analyzeAll isole les refus liés à la sécurité : 

final report = const JxParser().analyzeAll(saisie);
if (report.securityFailures.isNotEmpty) {
  // Refuser la saisie ou la signaler.
}

À savoir

Le contenu de jx.yaml (thème, breakpoints) n'est pas validé : il est écrit par le développeur du projet et considéré comme fiable.

Signaler une faille

N'ouvrez pas d'issue publique. La marche à suivre est décrite dans SECURITY.md, à la racine du dépôt.
