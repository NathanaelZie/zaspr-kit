Premiers pas

Ligne de commande

La CLI jx initialise un projet, compile les classes trouvées et surveille vos sources.

Toutes les commandes se lancent depuis la racine du projet avec dart run jx_cli:jx.

jx init

Crée un jx.yaml commenté. Refuse d'écraser un fichier existant, sauf avec --force.

$ dart run jx_cli:jx init
Option Rôle
-f, --force Écrase un jx.yaml existant.

jx build

Analyse les sources, compile les classes trouvées et écrit la feuille de style.

$ dart run jx_cli:jx build
Option Rôle
-c, --config Fichier de configuration (défaut : ./jx.yaml s'il existe).
-i, --input Expression de classes à compiler directement, sans scan.
--content Fichiers ou dossiers à scanner ; remplace content de jx.yaml.
-o, --output Chemin du fichier CSS généré.
-m, --minify Minifie le CSS de sortie.
--[no-]reset Inclut ou non le preflight.
-w, --watch Reconstruit à chaque modification des sources.

Compiler une expression

Avec --input, la CLI compile les classes données et affiche le CSS, sans lire vos fichiers :

$ dart run jx_cli:jx build -i "p:4 hover:c:blue"

Extraction des classes

La CLI ne lit que les chaînes de caractères de vos fichiers : chaque mot qui respecte la syntaxe JX et correspond à une règle devient une classe. Les mots qui ne correspondent à rien sont ignorés.

Classes dynamiques

Écrivez toujours les classes en entier. Une classe construite par interpolation, comme 'c:${couleur}', ne peut pas être trouvée : utilisez une table de littéraux complets.
