Nouveautés de la 0.2.0

Mode sombre, groupes, filtres, dégradés, animations, et un parseur qui refuse toute valeur capable d'injecter du CSS.

Nouvelles variantes

  • dark: suit la préférence du système, ou une classe .dark avec dark_mode: class.
  • group-hover:, peer-checked: et les autres group-* / peer-* réagissent à l'état d'un parent ou d'un frère.
  • motion-safe:, motion-reduce:, print:, contrast-more:, portrait:, landscape:.
dark : bg : gray-900 
@media (prefers-color-scheme: dark) {
  .dark\:bg\:gray-900 {
    background-color: #111827;
  }
}
group-hover : c : blue 
.group:hover .group-hover\:c\:blue {
  color: #3b82f6;
}
motion-reduce : anim : none 
@media (prefers-reduced-motion: reduce) {
  .motion-reduce\:anim\:none {
    animation: none;
  }
}

Messages et diagnostics

Une classe mal écrite est signalée avec une correction, proposée seulement si elle compile. Une valeur inconnue liste les valeurs possibles. 

Avertissement: Syntaxe de classe invalide : "hover:hover:c:red" (variante "hover" répétée).
Avertissement: Classe "pd:4" inconnue : vouliez-vous dire "p:4" ?
Avertissement: "c:bleu" ignorée : Valeur "bleu" invalide pour "c". vouliez-vous dire "c:blue" ? ; valeurs possibles : transparent, current, black, white, gray, gray-100, gray-300, gray-500, gray-700, gray-900, red, red-100… ; ou une valeur arbitraire entre crochets.

En Dart, JxParser.analyze retourne la raison du refus sous forme de code : unsafeValue, duplicateVariant, invalidValue…

Sécurité

Les valeurs entre crochets sont validées avant d'être écrites dans la feuille de style. Le détail est sur la page Sécurité.

Migrer depuis la 0.1

  • Une valeur simple ne commence plus par un point : lh:.5 est refusé, écrivez lh:[.5].
  • Dans une valeur arbitraire, ;, {, }, <, ! et \ sont refusés.
  • Les _ d'un url(…) ne sont plus convertis en espaces. Pour un _ littéral ailleurs, écrivez \_.
  • tx: et ty: produisent une variable --jx-tx / --jx-ty : le rendu est identique, le CSS généré change.
