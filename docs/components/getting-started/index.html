Components

Getting started with components

Install jx_cli, list the components folder, and use them like any Jaspr component.

Installation

The components ship inside jx_cli: one dependency gives you the compiler, the CLI and the components.

Coming from jx_ui

The components need jx_cli 0.0.3 or later. They used to ship as the separate package jx_ui, now discontinued: replace it with jx_cli and import package:jx_cli/ui.dart.

Configuration

The CLI only compiles the classes it finds. Add the components folder to packages in jx.yaml, so the classes used inside the components reach your stylesheet:

New

Components with callbacks (onClick, onInput, onChange) need to run in the browser: use them inside a @client component or a page that hydrates.

Theming

The components use five color families of the theme: blue for actions and focus, gray for text and surfaces, red, green and yellow for the tones. Redefine them in jx.yaml and every component follows:

Token Used for
blue-700 Primary buttons, checked controls, progress bars, links in tables.
blue-500 Focus ring, focused field border.
blue-100 Info badge and alert, row hover.
gray-900 / gray-100 Strong text in light and dark mode.
gray-100 / gray-700 Borders of cards, tables, dialogs.
red-*, green-*, yellow-* Danger, success and warning tones; field errors.

The focus ring, strong text and surface borders are shared tokens inside the components, so a button, a field and a dialog always focus and outline the same way.

Dark mode

Surfaces, text and borders have dark: variants and follow the system setting. Toggle your system theme to see the previews switch.

Design principles

  • Native first: <button>, <dialog>, <details>, <select>, real checkboxes. The browser handles focus, keyboard and announcements.
  • No JavaScript needed to render: modals, drawers and accordions open with HTML alone.
  • Visible focus on keyboard use only (focus-visible), never removed.
  • Motion stops when the system asks for reduced motion.
  • Touch targets of at least 40 px on buttons and controls.
  • Your state, your data: tables and pagination report events, you decide what to render.
