Architecture

Sept packages Dart indépendants et testés, chacun responsable d'une étape du pipeline. Utilisez le moteur seul, remplacez le thème ou ajoutez vos propres règles.

Le pipeline

Une chaîne de classes traverse quatre étapes : le parseur la découpe en jetons, le registre trouve la règle de chaque identifiant, le thème résout les valeurs nommées et le générateur écrit le CSS. 

"md:hover:bg:blue!"
  -> jx_parser     jeton : variantes [md, hover], bg, blue, important
  -> jx_rules      règle background-color
  -> jx_theme      blue = #3b82f6
  -> jx_engine     sélecteur .md\:hover\:bg\:blue\!:hover dans @media (min-width: 768px)
  -> jx_generator  CSS final
md : hover : bg : blue ! 
@media (min-width: 768px) {
  .md\:hover\:bg\:blue\!:hover {
    background-color: #3b82f6 !important;
  }
}

Les packages

  1. 01
    jx_core

    Contrats et modèles partagés : jetons de classe, règles CSS, configuration.

  2. 02
    jx_parser

    Analyse la syntaxe [variantes:]identifiant[:valeur][!], explique chaque refus et bloque les valeurs capables d'injecter du CSS.

  3. 03
    jx_theme

    Tokens du thème (couleurs, espacements, breakpoints…), extensibles par configuration.

  4. 04
    jx_rules

    Le catalogue des utilitaires et leur registre : chaque règle produit des déclarations.

  5. 05
    jx_engine

    Orchestre le pipeline et applique les variantes, en tri mobile-first.

  6. 06
    jx_generator

    Sérialise le CSS, minifié ou non, précédé du preflight.

  7. 07
    jx_cli

    jx build et jx init : extraction des classes des fichiers Dart, mode watch.

Ordre des règles

Le moteur trie la feuille en mobile-first : les règles sans requête média d'abord, puis les breakpoints par largeur croissante. Une classe md: l'emporte donc toujours sur la même propriété sans variante.

À savoir

Les décisions de conception (pseudo-éléments en fin de sélecteur, anneau de focus par propriété personnalisée…) sont documentées dans docs/architecture.md du dépôt.
